# Decision log

Resolved and deferred items, so they are not re-interpreted.

## Resolved

- **Repository and stack:** `marin-reach`, built from `marin-app-template`. Static site, committed JSON, no site build step.
- **Order:** the list, CSV and copied text show the newest date first and the oldest at the bottom, with the earliest start time first within a day. The calendar still orders each day by start time, and the RSS feeds are newest first.
- **Layout:** follows marin-mentions: tablist tabs, a "Showing:" line, Reset under search, and Copy / Link / CSV / RSS buttons on the list and Copy / All PNG / Link on Stats. No intro text or visible page heading on the primary page.
- **Sidebar order:** Date, then collapsed dropdowns for Audience, Type, Project, Agency/Department, Partner, Status, Location, then Owner. The dropdowns follow the monitor groups in marin-mentions and open on their own when they hold a selection. "Type" is the Type of Engagement field and "Location" is the filter label for the Geographic Area field; the venue text stays a listing field and is not a filter.
- **Copy:** copied text has no emoji, no "Showing:" prefix and no date after the "Marin Reach" heading. Each listing has its own Copy button. Action messages ("Copied 3 engagements to clipboard.") appear directly below the button row, or below the listing's own button.
- **Selection:** a checkbox per listing. Copy and CSV act on the checked listings, or on everything shown when none are checked. Selection is not saved in the URL.
- **RSS:** static feeds generated by the data build (`feeds/all.xml`, `feeds/project-<slug>.xml`). The RSS button is enabled only for all engagements or a single project with no other filter, search or date range.
- **Primary view:** a list. Calendar and Stats are secondary and use the same filtered records. Views switch in place (query parameter `view`), so filters are never reset.
- **Dataset:** JSON generated from the supplied CSV. The CSV is the editable source.
- **Field names:** `Partner` replaces the spec's "Organization/Group". `Event Name` replaces "Event Name (If Applicable)". `Audience` is an added field, used as a filter and detail field.
- **Status:** `Planned`, `Canceled`, `Completed` as entered. Planned records with past dates stay Planned, with no warning. Canceled records appear in the calendar, struck through and labeled.
- **Stats:** Planned, Completed, Canceled, Partners, events over time (every month in the filtered set; no six-month default), by agency/department, by project.
- **Date filter:** a From and To range, inclusive, in the query string as `from` and `to`.
- **Aliases:** `CDA`, `OCE`, `D1` to `D5` are spelled out in `data/aliases.json`, with source values kept in `raw`.
- **Charts:** Chart.js canvases styled like marin-mentions (`#0777cf`), each with a text summary and a screen-reader-only data table. An earlier table-with-bars version was replaced at the owner's request.
- **Map and geocoding:** removed from v1. `Location` is plain text.
- **Metadata and notes:** not part of the model.

## Deferred

- A shared MarinOS reference-data library for organizations, departments and geography.
- API or subscription feeds for other MarinOS apps.
- Additional data sources normalized into the same schema.
- Submission and review workflow.
- Cleaning up Partner values that are not organizations when more data arrives; the ambiguity report is the intended signal.
- Authentication or a firewall (a hosting concern, out of scope).
- A map of locations, if reintroduced, needs its own approval for tiles, geocoding and the security policy.
