# Decision log

Resolved and deferred items, so they are not re-interpreted.

## Resolved

- **Repository and stack:** `marin-reach`, built from `marin-app-template`. Static site, committed JSON, no site build step.
- **Order:** the list, CSV and copied text show the newest date first and the oldest at the bottom, with the earliest start time first within a day. The calendar still orders each day by start time, and the RSS feeds are newest first.
- **Layout:** follows marin-mentions: tablist tabs, a "Showing:" line, Reset under search, and Copy / Link / CSV / RSS buttons on the list and Copy / All PNG / Link on Stats. No intro text or visible page heading on the primary page.
- **Sidebar order:** Date, then collapsed dropdowns for Audience, Type, Project, Agency/Department, Partner, Status, Location, then Owner. The dropdowns follow the monitor groups in marin-mentions and open on their own when they hold a selection. "Type" is the Type of Engagement field and "Location" is the filter label for the Geographic Area field; the venue text stays a listing field and is not a filter.
- **Copy:** copied text has no emoji, no "Showing:" prefix and no date after the "Marin Reach" heading. Each listing has its own Copy button. Action messages ("Copied 3 engagements to clipboard.") appear directly below the button row, or below the listing's own button.
- **Selection:** a checkbox per listing. Copy and CSV act on the checked listings, or on everything shown when none are checked. Selection is not saved in the URL.
- **RSS:** static feeds generated by the data build (`feeds/all.xml`, `feeds/project-<slug>.xml`). The RSS button is shown only for all engagements or a single project with no other filter, search or date range; otherwise it is hidden and there is no explanation text.
- **Primary view:** a list. Calendar and Stats are secondary and use the same filtered records. Views switch in place (query parameter `view`), so filters are never reset.
- **Dataset:** JSON generated from the supplied JSON-LD graph (`data/source/marin-reach-engagements.json`), which is the editable source. It replaced the earlier CSV source. Venue address and coordinates, and the verification notes in the source, are not carried into the dataset.
- **Field names:** `Partner` replaces the spec's "Organization/Group". `Event Name` replaces "Event Name (If Applicable)". `Audience` is an added field, used as a filter and detail field.
- **Status:** `Planned`, `Canceled`, `Completed` as entered. Planned records with past dates stay Planned, with no warning. Canceled records appear in the calendar, struck through and labeled.
- **Stats:** Planned, Completed, Canceled, Partners, events over time (every month in the filtered set; no six-month default), by agency/department, by project.
- **Date filter:** a From and To range, inclusive, in the query string as `from` and `to`.
- **Aliases:** `CDA`, `OCE`, `D1` to `D5` are spelled out in `data/aliases.json`, with source values kept in `raw`.
- **Charts:** Chart.js canvases styled like marin-mentions (`#0777cf`), each with a text summary and a screen-reader-only data table. An earlier table-with-bars version was replaced at the owner's request.
- **Map and geocoding:** removed from v1, then approved again for a Map view between Calendar and Stats. Leaflet 1.9.4 is vendored. Tiles come from OpenStreetMap's standard tile server (`tile.openstreetmap.org`), chosen over the USGS National Map for its street-level labels. It needed one host added to `img-src` in `security.json` (CSP update only; tiles are not self-hosted). Visitors' browsers request tiles from OpenStreetMap directly, so it sees their IP address. OpenStreetMap's [tile usage policy](https://operations.osmfoundation.org/policies/tiles/) allows light use only and may block heavy traffic; if Reach outgrows it, switch to the USGS National Map or a hosted provider (a one-line change to `TILES` in `assets/app.js` plus `img-src`). Attribution reads "© OpenStreetMap contributors" next to Leaflet's credit and must stay visible. Coordinates are read from the source data and never guessed or geocoded in the browser. There is no browser geolocation.
- **Map details:** a details panel below the map (not Leaflet popups) shows the selected engagement; events at identical coordinates share one marker and are listed in the panel; nothing shows below the map until a marker is chosen; each listing there has the same Copy button as List (no checkboxes, Close or Open details buttons); the Map toolbar has only Link; a status line above the map gives the mapped and unmapped counts for the filtered engagements; a Clear button under the map clears the selection and returns focus to the marker (Escape does the same from the details). Events without coordinates stay in List, Calendar and Stats.
- **Map extras:** a "Locations" dropdown (alphabetical, "All locations" by default and when cleared, focus stays on it and the change is announced) is a text alternative to the markers and changes with them; Re-center (compass icon) reframes every marker; the selected place is kept in the URL as `place=<latitude>,<longitude>` (map view only, dropped when the filters remove that place); each place has Copy (the place, its address and all its engagements) and, directly below its address, an icon-only Get directions button (Lucide `signpost`, styled like the Copy button); every listing and the details dialog has the same icon-only button to the right of Copy and Show on map when the engagement has an address or coordinates. Directions are a Google Maps link in a new tab, opened only when chosen, using the street address or else the coordinates. Cards inside a map location's details have no directions button, since the location's own is just above; listings and the details dialog have an icon-only Show on map button (map pin, styled like the Copy button) when the engagement has coordinates; engagements at one place list upcoming ones first (soonest first), then past ones (latest first); the mouse wheel and one-finger drag leave the page alone until the map is clicked or focused (phones pan and zoom with two fingers). Counts on grouped pins and a list of unmapped engagements were considered and not built.
- **Clusters and full window (2026-10-20):** Leaflet.markercluster 1.5.3 is vendored and groups nearby markers always, even with few locations (decided 2026-10-20 after the owner expected to see clusters with the 7 current locations; a first version only clustered from 12 locations). A single location is a pin. A cluster looks the same everywhere (Marin blue circle, white count), the number is engagements, its spoken name gives locations and engagements ("3 locations, 7 engagements. Press Enter to zoom in."), and Enter, Space or a click zooms in. Spiderfy and the hover coverage area are off. When a cluster splits, focus moves to the map. Choosing a clustered place from the Locations list or Show on map zooms to reveal it first. A Full window button (Lucide `fullscreen`, then `minimize` with "Exit full window") moves the map, its buttons, the Locations list and the details into a modal dialog that fills the browser window; it is not the browser's fullscreen mode. Escape closes it and focus returns to the button. Full window is not saved in the URL. The manual-copy box moves into the dialog while it is open.
- **Coordinates:** optional. Latitude and longitude must come together and be numbers in range or the build fails. Coordinates outside Marin County are kept and reported in `data/ambiguities.md`. Verification notes in the source stay in the source file and are not part of the dataset. Coordinates for Homestead Valley Community Center and the Marin Health & Wellness Campus Connection Center were added on 2026-10-19 from the US Census geocoder, and the OpenStreetMap geocoder agreed within about 4 meters; confirm them against a County source when convenient.
- **Metadata and notes:** not part of the model.

- **Collapsible filters (2026-10-22):** the filter sidebar can be hidden at any width. One icon-only, white Filters button sits at the top of the left column (above the filters; on narrow screens it is above the page and the panel opens below it). When the panel is hidden the column shrinks to just the button. Icons are Lucide `panel-right-open` while the panel is open and `panel-left-open` while it is hidden. It has no visible text; its name is "Filters" (or "Filters, N active"), with `aria-expanded` and `aria-controls`. Hiding the panel keeps every filter applied, removes the panel from the tab order, keeps focus on the button, and lets the results use the full width. Wide screens start open and remember the choice in this browser (`localStorage` key `reach.filters`, optional); narrow screens start closed and do not save it. The map measures itself again after each change. The choice is not in the URL. The behavior and styles now come from Marin UI 1.28.1 through Marin App Shell 1.14.0 (`button.filter-toggle[data-filter-toggle]`, `data-filter-active`, the `marin-filters-change` event); the app only keeps the active count current and measures the map again. The remembered choice is stored under `marinos.filters.marin-reach.filters` (`<body data-app-id="marin-reach">`). `marin-mentions` uses the same shared button.

## Deferred

- A shared MarinOS reference-data library for organizations, departments and geography.
- API or subscription feeds for other MarinOS apps.
- Additional data sources normalized into the same schema.
- Submission and review workflow.
- Cleaning up Partner values that are not organizations when more data arrives; the ambiguity report is the intended signal.
- Authentication or a firewall (a hosting concern, out of scope).
- Self-hosted map tiles, if the tile host is not acceptable to the privacy review.
- Adding real coordinates for the events that have none; that is a data task for the source owners.
